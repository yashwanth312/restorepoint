# Active Directory `rp.test` baseline: size and object counts, before and after test users

- Date: 2026-11-14 12:40 to 12:46 (America/Chicago, UTC-06:00)
- Host: Windows Server 2025 domain controller `RP-DC01` (VM `rp-ad`, 10.77.0.11), PowerShell over SSH from the Proxmox host
- Sources: [before](2026-11-14T1240-ad-baseline-before.png), [after](2026-11-14T1246-ad-baseline-after-users.png)

## Before

| Check | Result |
|---|---|
| `(Get-Item C:\Windows\NTDS\ntds.dit).Length` | 41,943,040 bytes (40 MB) |
| `(Get-ADObject -Filter *).Count` | 242 |
| `(Get-ADUser -Filter *).Count` | 3 (Administrator, Guest, krbtgt) |
| `Get-ADDomain` | `rp.test`, NetBIOS `RP`, `Windows2025Domain` |

## Test users added

An organizational unit `rp-staff` under `DC=rp,DC=test`, and 25 users `user01` to `user25` in it, created with `New-ADUser ... -Enabled $false`. They are disabled and have no password, so nothing sensitive is stored in the lab.

## After (healthy, before any backup or fault)

| Check | Result |
|---|---|
| `(Get-ADUser -Filter *).Count` | **28** |
| `(Get-ADObject -Filter *).Count` | **268** (242, plus the OU, plus 25 users) |
| `ntds.dit` length | **41,943,040 bytes**, unchanged |

Method: the PowerShell commands above, run on the domain controller. The restore checks in Phases 2 and 5 compare against 28 users and 268 objects after a restored domain controller boots.

## Prediction check

Predicted before the first run: `ntds.dit` 15 to 25 MB, 150 to 250 objects, 3 users, `rp.test`/`RP`/`Windows2025Domain`. Measured: 40 MB (outside the range; the file is pre-sized and grows in fixed chunks, so a fresh domain already has a large file), and the other three inside. Predicted after adding users: 28 users, 268 objects, `ntds.dit` unchanged. All three held. Because the file size does not move with 25 users, object counts are the check that shows the content, not the file size.
